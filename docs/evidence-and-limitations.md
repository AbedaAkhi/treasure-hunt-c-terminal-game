# Evidence and Limitations

## Uploaded source materials reviewed

1. `progress.docx` — lengthy iterative development notes containing C code fragments and alternate versions; not a definitive final source snapshot.
2. `screenshot.zip` — screenshots showing terminal gameplay, win/lose output and other development evidence.
3. `Short Report ... .docx` — describes difficulty zipping the submission and contains screenshots of installation/archive problems; not a technical implementation report.
4. `UCP_2024_S2_Assignment.pdf` — official assignment requirements and publishing warning.
5. `stepts to follow.docx` — instructions/guidance for approaching the task, not independently authored implementation evidence.
6. Three supplementary video ZIP archives — sample code, teaching material and videos on sleep, random numbers and terminal character input; **excluded** from portfolio.
7. `COMP1000 ... .pdf` — official unit outline; context only.
8. `Declaration of Originality ... .pdf` — private coursework form; excluded.

## What is supported

- C-language game logic, file-driven map, basic terminal movement, snake logic and win/loss checks appear in the development document.
- Screenshots demonstrate that a game version ran in a terminal and displayed game-end output.
- Build configuration is present in progress notes.

## What is not verified

- A single final submitted source tree, complete build from that tree, or fresh regression tests.
- Fully working UNDO or DARK mode.
- Dynamic map allocation (an early main.c version defines a fixed 15x20 array).
- Full compliance with the assignment specification (which includes specific C89, memory management and gameplay rules).

No code was rebuilt or executed for this documentation-only portfolio. The materials come from 2024 and the development files contain multiple drafts.
